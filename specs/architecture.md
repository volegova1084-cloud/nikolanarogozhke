# Архитектура статического frontend

- Простые HTML-файлы, CSS3, vanilla JavaScript и **локальный Bootstrap 5.3.x**, без npm и сборщиков.
- Статический прототип, не включать PHP/Bitrix API. Страницы организовать так, чтобы разметку было впоследствии удобно перенести в шаблоны CMS.
- `concepts/concept-01.html`…`concept-03.html` — три отдельные концепции главной; `concepts/index.html` — галерея с тремя реальными превью и ссылками.
- `css/` — локальная библиотека Bootstrap и минимальные стили дизайна (при необходимости отдельные стили концепций); `js/` — поведение; `images/` — фото, SVG, превью, с источниками/лицензиями в `specs/assets.md`.
- Пути относительные и работающие под подкаталогом GitHub Pages, никаких абсолютных `/css/...`.
- В первом запуске не нужно делать функциональную CMS и полный набор внутренних страниц; в `specs/pages.md` описать будущие шаблоны.
- Графика должна быть оптимизированной и локально доступной. Для карт допустим iframe внешнего картографического сервиса при действующей политике встраивания; обязательно обозначить, если карта лишь заглушка.
- Публикация GitHub Pages только после одобрения. Рабочую и publish-ветки не смешивать; точную схему развёртывания документировать в README.

## Реализация этапа 1
Bootstrap 5.3.3 (MIT), css/bootstrap.min.css; css/fonts.css и локальные TTF (OFL); css/concepts.css — общий дизайн и body-классы concept-01/02/03; js/concepts.js — меню и диалог будущих разделов. Каждая концепция содержит самостоятельную семантическую HTML-разметку. Галерея имеет реальные превью, если браузер доступен, иначе честное указание ограничения. Нет runtime CDN.

## Сборка главной для просмотра
index.html — цельная главная по выбранной концепции 01, все пути относительно корня. review/index.html — просмотр структуры по реальным скриншотам секций с переходом на живой HTML-макет. concepts/ остаётся галереей направлений. images/previews/homepage/ содержит фактические снимки собранной страницы. Публикация отдельно не запрошена.
