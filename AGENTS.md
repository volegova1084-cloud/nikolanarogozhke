# Постоянные правила для Codex

Проект: редизайн сайта https://nikolanarogozhke.ru/. Общение, спецификации и отчёты — **на русском**. HTML-контент — русский; имена файлов, CSS-классов, JavaScript-переменных и комментарии в коде — английские.

## При начале любой сессии
Прочитай `specs/requirements.md`, `specs/design.md`, `specs/architecture.md`, `specs/pages.md`, `specs/progress.md`; при анализе визуальной части читай `specs/reference-analysis.md` и `specs/assets.md`. Прочитай мастер-промпт, если ещё не выполнен первый этап. Сначала изучи git status и существующие файлы. Не затирай чужую работу.

## Стек и запреты
HTML5, CSS3, vanilla JS, **локальный Bootstrap 5.3.x**, 12 колонок; без сборки/npm, PHP/Bitrix API, React/Vue, Tailwind, Sass. Проект — статический frontend с возможностью последующего переноса в Bitrix. Используй семантику и базовую доступность. Учитывай путь GitHub Pages в подкаталоге. Минимум дополнительных зависимостей и анимаций.

## Дизайн
Согласованный визуальный бриф хранится в `specs/design.md` и `specs/requirements.md`. Приоритет — прихожане; тональность — современная православная, светлая, просторная, с природной зелёной палитрой, классическими заголовками и современным текстом. Bootstrap — базовая система компонентов; индивидуальность создаётся контентом, композицией, фотографиями и тонким SVG-декором. `design.md` — подробный справочник, допускающий самостоятельные решения в согласованной эстетике.

## Контент и графика
Никаких вымышленных исторических фактов, святынь, расписаний, новостей, служителей, адресов и телефонов. Явно помечай placeholders. Реальный храм нельзя подменять другой церковью. Проверяй права и записывай источники графики в `specs/assets.md`.

## Процесс
Гибкий Spec First: изучи, уточни спецификации, реализуй, протестируй, обнови `specs/progress.md`. Первый запуск: 3 полноценные концепции главной + галерея. После готовности концепций нужна контрольная точка с выбором пользователя; финальный дизайн и внутренние страницы до утверждения НЕ разрабатывать.

## Git и публикация
После значимых готовых этапов создавай содержательные коммиты на английском, если доступ разрешён. Работай безопасно в рабочей ветке; не делай force push, не удаляй утверждённые файлы. GitHub Pages — только для одобренных версий: **самостоятельно не публикуй и не переключай настройки GitHub Pages**. Коммит ≠ публикация. Любые недоступные инструменты и непроверенные шаги отмечай честно.

## Контроль качества
Проверяй адаптивность на 1440, 1024, 768, 375, 320 px, без горизонтального скролла; поведение ссылок, меню, форм, семантику, клавиатуру, контраст, отсутствие JS-ошибок. Если браузер и инструменты не доступны — запиши ограничения, не симулируй прохождение тестов.
